## Q1. 信号暴露策略:哪些节点需要渲染数据端口的信号点?

**背景**:内核语义中每个数据端口都带信号电平(输入信号 = 该端口是否启用,
输出信号 = 自动传导)。v3 视觉语言目前为**所有**数据端口渲染一对竖直堆叠
的"信号点 + 数据点"。

**问题**:不是每个节点都需要暴露信号点——

- **Join 必须暴露**:单数据路径与双数据路径的区分依赖信号(数据线把值送到
  了,但端口信号被关闭 = 值不参与),不暴露就无法表达"单数据 vs 双数据";
- **Random 不必暴露**:seed/range 是 draw 时的参数,运行时不需要用信号来
  关闭种子或范围,暴露信号点反而显得复杂;
- 其余节点(哪些暴露、哪些隐藏)待逐个裁定。

**关键澄清**:隐藏信号点 ≠ 删除信号语义。内核侧每端口仍带电平(自动传导、
显式屏蔽的机制不变),"暴露"只是**编辑端的视觉概念**——隐藏的信号点仍在
语义上存在,只是不在节点面上渲染(也不可连线,走默认自动传导)。

**可选方向**:

1. 内核 NodeType 增加声明(如 `expose_signals: bool` 节点级,或端口级
   `DataIn.expose_signal`),由节点作者声明,编辑器照声明渲染——符合
   "视觉语言由内核声明派生"的原则;
2. 编辑器启发式派生(如"有绑定端口的节点不暴露"),零内核改动但规则与
   语义脱节;
3. 折中:默认暴露,声明关闭(opt-out)——与当前视觉一致,改动最小。

**待讨论**:声明形态(节点级/端口级)、默认值(暴露/隐藏)、首批隐藏名单。

## Q2. 数据转信号节点(Data → Signal)

**背景**:信号控制最需要的节点——把数据值转换为信号电平(数据面 → 信号面),
这是数据与信号两个正交网络在"信号层"汇合的关键入口。

**问题**:数据如何转换成信号,语义有待商榷:

- 阈值判定?(value > threshold → 高/低)
- 真值判定?(非零/非空 → 高)
- 多条件组合?(与已有 Comparator/Threshold 数据节点的关系?)

**倾向方向**:最自由的方式是支持**自定义脚本实现转换**——脚本节点已支持
用户自定义(内核 1.2),转换规则由用户脚本表达,节点形态(端口声明)由脚本
编译产物决定。

**待讨论**:节点形态(固定端口契约 vs 脚本自由声明)、转换语义(电平更新
时机:每值到达 / 每轮)、与脚本节点的关系(独立节点类型 vs 脚本节点特例)、
与 Threshold/Comparator 的边界(它们产出数据,不产信号)。
