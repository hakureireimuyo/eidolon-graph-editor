## Q1. 端口组合级别:不同节点真正需要什么级别的端口?

**背景(2026-08-18 修正)**:此前的问题被错误地框定为"哪些数据端口需要暴露
信号点"——即假设**所有数据端口都可被信号控制**,只是编辑端选择隐藏与否。
这个假设本身不成立:**并非所有数据都可以被信号端口控制**。

**正确的问题**:不同节点真正需要什么**级别的端口组合**——这是内核声明模型
的问题,不是编辑端"标记暴露"的问题。

**观察**:

- **Join 需要信号控制**:单数据路径与双数据路径的区分依赖端口信号(数据线
  已送达但端口被关闭 = 值不参与),因此 Join 的输入端口必须是"信号+数据"
  完整端口;
- **Random 不需要**:num/seed/range 是 draw 参数,运行时不需要用信号关闭
  种子或范围——它的端口只要"值到达即参与"的纯数据端口即可;
- 信号元件(AND/OR/NOT/Latch)只需要纯信号端口;部分节点需要节点级门控
  (enable)——现有 ControlIn 已表达。

**候选端口组合级别**(待讨论):

| 级别 | 端口形态 | 语义 | 例子 |
|---|---|---|---|
| 纯数据端口 | 仅数据点 | 值到达即参与;无信号、无屏蔽、无自动传导 | Random 的 num/seed/range? |
| 信号+数据对 | 信号点+数据点(现状) | 端口可被信号关闭(显式屏蔽/自动传导) | Join 的 a/b、Counter 的 increment? |
| 纯信号端口 | 仅信号点 | 电平组合/门控(现状 ControlIn/Out) | AND/OR、enable |
| 节点级门控 | 整节点 enable(现状) | 低电平 = 节点不执行、输出关闭 | Counter/Switch 的 enable |

**关键推论**:"暴露"是视觉概念的观点作废——如果 Random 的端口在**内核语义
上就没有信号**,编辑端自然只渲染数据点,不存在"隐藏"。反之 Join 的端口在
语义上带信号,编辑端必须渲染信号点。

**可选方向**:

1. 端口级声明:DataIn 增加字段(如 `signal: bool`,或反向 `plain: bool`),
   由节点作者逐端口声明——最细粒度,但声明面变大;
2. 节点级声明:NodeType 增加端口模型级别(如 `port_model: Literal[...]`),
   整节点一档——粗粒度,但组合异构(如"参数无信号、数据输入有信号")
   表达不了;
3. 语义推导:如"optional/绑定端口天然不需要信号控制(值回退配置/常量),
   仅必需连线端口带信号"——零声明,但规则是否与所有节点直觉一致待验证
   (Timer 的 delay 是 optional,是否需要信号控制?);
4. 端口类型分化:PlainDataIn vs DataIn 两种端口类——声明清晰,但内核模型
   和校验/运行时都要双轨。

**运行时影响**(任一方向都要回答):无信号端口的组触发策略如何判定
(不看信号,只看值到达?)、校验如何把关(不允许信号线连到无信号端口?)、
输出侧无信号的端口是否还有自动传导。

**待讨论**:选定方向 + 首批哪个级别给哪些节点(逐个裁定:Random 之外还有
哪些节点不需要信号控制?)。

## Q2. 数据转信号节点(Data → Signal)

**背景**:信号控制最需要的节点——把数据值转换为信号电平(数据面 → 信号面),
这是数据与信号两个正交网络在"信号层"汇合的关键入口。

**问题**:数据如何转换成信号,语义有待商榷:

- 阈值判定?(value > threshold → 高/低)
- 真值判定?(非零/非空 → 高)
- 多条件组合?(与已有 Comparator/Threshold 数据节点的关系?)

**倾向方向**:最自由的方式是支持**自定义脚本实现转换**——脚本节点已支持
用户自定义(内核 1.2),转换规则由用户脚本表达,节点形态(端口声明)由脚本
编译产物决定。

**待讨论**:节点形态(固定端口契约 vs 脚本自由声明)、转换语义(电平更新
时机:每值到达 / 每轮)、与脚本节点的关系(独立节点类型 vs 脚本节点特例)、
与 Threshold/Comparator 的边界(它们产出数据,不产信号)。
